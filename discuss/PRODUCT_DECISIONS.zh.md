## DeepSeek 接口修正（2026-09-16）

用户提供的 `https://api.deepseek.com/anthropic` 是官方兼容接口 Base URL。模型发现应使用同域 `GET /models` 与 Bearer 鉴权；Anthropic 生成使用 `POST /anthropic/v1/messages` 与 `x-api-key`。不能把两种操作都直接拼到兼容前缀下。模型列表返回 404/405 时仍允许手动填写模型 ID 并测试生成。

公开依据：[DeepSeek Anthropic API](https://api-docs.deepseek.com/guides/anthropic_api)、[DeepSeek Models API](https://api-docs.deepseek.com/api/list-models)。本次没有读取或使用截图中的密钥。

## 自主开发授权后的工程决定

- 用户已授权自行确定合适目标并开发，Electron + TypeScript 是最终交付形态，不能以浏览器原型代替。
- 三种协议选定 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages；代码允许配置兼容服务 URL。
- 官方绑定选定 React，保留 Vanilla API。主进程执行文件与网络操作，沙箱 preload 暴露有限接口。
- AI Key 使用 Electron safeStorage 系统加密；切换服务地址时旧密钥不自动发给新地址。
- 无真实 API Key：本地 HTTP 协议测试与桌面请求流程由开发阶段完成，真实服务联调由用户提供凭据后执行。
- 默认中文、深色安静写作界面，提供浅色主题；使用 Markz 作为工作名称。
- 性能预算、默认主题/面板、产品名称及许可证：需求稿有明确建议或待定标识，不作为用户已经确认的事实。

## 编制时采用的工程解释

- “带 AST”不等于要求每次输入把 AST 重新序列化成 Markdown；普通编辑与 AI 修改都作用于精确文本范围。
- “性能化”不等于保证任何 Markdown 改动都只解析固定几行。允许在后台处理全局语法影响，验收输入延迟、索引一致性和完整语义。
- “无头”与“漂亮 UI”通过可独立使用的核心和可选官方 UI 同时满足。
- “轻量”与“完整 AI”通过独立模块和按需加载同时满足；AI 仍然属于这次交付。
- “本地优先”不排斥用户主动配置外部模型；发给模型的上下文和服务地址对用户可见。
